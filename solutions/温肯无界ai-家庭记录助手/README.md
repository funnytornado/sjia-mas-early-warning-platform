# 家庭记录助手

原生微信小程序：把**化验、症状、用药**三类内容记在一起，看趋势、生成就诊摘要、离线导出 Word（.docx）。纯本地离线工具：做记录整理，并按已发表标准给出提示（见「评估」页）；不作诊断、不给治疗或用药建议。

## 这个工具做什么、不做什么

- **做**：记录与整理你自己录入的化验项目、症状、用药；按日期画数值趋势；把你录入的内容整理成就诊摘要并导出 Word。
- **不做**：不做诊断、不给治疗或用药建议、不替代医生判断。

## 导航结构

- **底部原生 tabBar 两项：记录 / 发现**。
- **每个页面顶部有一条可点的子导航**：记录页是 概览 / 记录 / 历史 / 趋势 / 摘要，发现页是 就医资源 / 政策资讯，滚动时吸顶。

## 最快上手

1. 在微信开发者工具中导入本目录，根目录是包含 `project.config.json` 的 `sjia-demo`。
2. `project.config.json` 里已写着一个 AppID；换成自己的也行。
3. 全程本地离线：数据存在微信本地存储，Word 导出也在手机上离线生成，不联网、不需要任何后台。
4. 在「记录」页手动录入化验、症状与用药；数据只保存在本机，不联网、不上传。

## 记录页：三类记录

- **化验**：采样日期、报告名称、任意检查项目（名称 / 结果 / 单位 / 参考范围 / 报告异常标记），支持拍照或上传图片作附件。
- **用药**：药名、剂量、用法频次、开始日期（必填）、结束日期（留空即「仍在用」）、备注。按医生嘱咐或药盒原样填写，本工具不做换算、不做剂量建议。
- **症状**：日期 + 文本，可叠加常用症状标签。

## 评估页：按已发表标准给提示

「评估」页把你录入的化验值与临床项，按三套已发表标准算一遍，**只作提示，不是诊断**：

- **2016 PRINTO/ACR/EULAR MAS 分类标准**：前提是确诊或疑似 sJIA；必备条为发热 + 铁蛋白 > 684 ng/mL，再加附加条目任意 2 条（血小板 < 181×10⁹/L、AST > 48 U/L、甘油三酯 > 156 mg/dL、纤维蛋白原 < 3.6 g/L）。
- **2004 HLH 诊断标准**：八条中符合五条。其中 NK 细胞活性、sCD25、噬血现象需要特殊检查或病理，本工具拿不到，会明确标为「无法评估」，不会当成阴性。
- **MS 评分表（MAS/sJIA）**：按公布系数计算，≥ -2.1 提示可能性大。

**已知缺陷（原样计算，未擅自修正）**：MS 评分公式按原文计算时，一个各指标都正常的儿童也可能得到约 -2.0、越过 -2.1 的判定线；结果卡里会直接写明。另外原文未给常数项，分数按缺常数项计算。

标准配置与判定逻辑移植自本机另一工程 `sjia预警系统`（`engine/standards.toml`、`engine/sjia_engine/static_monitor.py`），小程序内对应 `miniprogram/utils/standards.js` 与 `utils/assess.js`，回归用例在 `checks/assess.test.js`。本工具**不是医疗器械**，评估结果不能作为诊断依据，必须由医生判断。

## 导出 Word（.docx）

- **摘要页**：选日期区间 → 生成摘要 → 「预览 Word 摘要」在内打开，「发送 Word 到聊天」转发给自己或医生，另有「复制纯文本」。
- **单份报告**：在「历史」里打开一份报告，可「预览 Word 报告」「发送 Word 报告」。
- 化验项目与用药记录是**真正的 Word 表格**；文档末尾写明内容来自本人录入、不构成诊断建议。
- 实现上不依赖后端或第三方库：`.docx` 本质是装了 XML 的 ZIP 包，工程内 `utils/docx.js` 现场拼 ZIP（store 方式 + 自写 CRC32 + UTF-8 编码器）并写 WordprocessingML，再用 `wx.getFileSystemManager().writeFileSync` 落盘、`wx.openDocument` 预览、`wx.shareFileMessage` 转发。

## 发现页：形态演示，不是真实信息

两栏都是**写死的样例数据**：就医资源（按城市 + 科室筛选样例医院）、政策资讯（按地区筛选样例政策摘要）。查看原文、预约入口、复制地址等只弹演示提示，不发任何网络请求。页面顶部与每张卡片都标注「演示数据，非真实来源」，并写明不提供诊疗建议与预约挂号。

## 数据与边界

- 数据保存在微信本地存储（键 `sjia-records-v1`）；清空会删除本设备上的全部记录且不可恢复。
- 无账号体系、无云端同步、无后端服务；换设备数据不跟随。
- 图片只作附件保存在本机；**不做图片识别，不包含 OCR**。
- 记录数据全部由你自己录入；「发现」页里的医院与政策是明确标注的演示数据，不是真实信息。

## 发布前检查（个人主体 · 当前不可走公开发布）

> 工程已包含按临床标准的评估功能，**个人主体无法开通医疗健康类目，因此提审必被驳回**。当前只走「体验版 + 体验成员白名单」内测；要公开发布必须先换医疗机构/企业主体并办理相应资质。以下步骤仅在取得资质后适用。

如果你要把它公开发布给任何微信用户，按下面顺序走。**这些是平台硬要求，不是代码问题：**

1. **确认主体与类目**：个人主体**不能开通医疗健康类目**，所以类目要走「工具」这类；名称、简介、界面文案都不能出现诊断、治疗、用药建议等表述（当前版本已按此清理）。
2. **完成小程序备案**：2023 年起强制，未备案不能发布；个人主体可用身份证 + 手机 + 邮箱备案。
3. **填写用户隐私保护指引**：本工程用到相册/摄像头（`wx.chooseMedia`）、文件写入与转发（`writeFileSync`/`openDocument`/`shareFileMessage`），这些属于隐私相关接口，必须在后台的隐私指引里声明，否则相关功能会被拦截。
4. **提交审核**：审核看的是「类目是否匹配、有没有资质、有没有违规内容」。
5. **病友交流（UGC 社区）已删除**；剩余的就医资源仍属「医院信息」形态，写死样例数据不等于没有风险。若要进一步降低，可把「发现」换成只讲数据只存本机、非医疗器械、隐私说明的「关于」页——同样满足 tabBar 至少两项。
