# 演示前验收

## 已在本机实跑验证

- JavaScript 语法与 JSON 配置（`node checks/check.js`）
- WXML 编译陷阱回归检查：表达式里不得出现 HTML 实体 `&amp;&amp;`；`wx:else` 不得带值（这两处曾导致真实编译失败）
- 导航结构回归检查：每个页面都有顶部子导航 `class="subnav"`；不得再出现旧的固定底栏 `class="tabs"`；不得再有给页内 tab 加 tabBar 高度偏移的写法
- 改名残留检查：`miniprogram/` 下不得再出现旧名「小航」
- 社区移除检查：不得再出现「病友交流」「发帖」「举报」；发现页数据模块不得再导出帖子与主题数据
- 演示与设置移除检查：不得再出现「演示时间线」「演示样例」「加入下一次模拟记录」「data-tab="settings"」；`utils/samples.js` 不得再打进小程序包
- **涉医字样与风险分级检查**：`miniprogram/` 下不得出现「预警」「规则命中」「MAS」以及 `GREEN`/`YELLOW`/`INSUFFICIENT`/`statusLabels`；`engine` 不得再导出风险分级函数；`store.state()` 不得再返回风险字段
- `input` 必须显式指定高度（微信 `input` 默认高度不随字号增长，会把文字裁切）
- 原生 tabBar 与 `pages` 列表一致，页面文件齐全
- 单位换算（甘油三酯 mmol/L、纤维蛋白原 g/L）与「最近一份报告未包含的项目」计算正确
- 摘要时间范围筛选，以及「用药记录」段落随区间变化
- **Word 生成**：CRC32 与标准测试向量一致；生成的 `.docx` 以 ZIP 头 `PK\x03\x04` 开头，包含三个必需部件，含 `<w:tbl>` 表格；`&`、`<`、`>` 被正确转义；摘要与单份报告都能生成
- 本地存储：化验 / 用药 / 症状的新增、修改、删除；没有 `medications` 字段的旧数据能兼容为空
- 发现页数据自检：演示标注、演示来源、筛选结果、页面边界说明（仅就医资源与政策资讯两栏）

## 需要导入开发者工具后人工验收

- 导航栏与两个页面头部显示「家庭记录助手」，没有任何旧前缀。
- 底部原生 tabBar 两项可点击切换；顶部子导航可点击且滚动时吸顶；页面不被固定栏遮挡。
- 记录页顶部只有五个子导航「概览 / 记录 / 历史 / 趋势 / 摘要」，「设置」已移除；概览页不再有「演示时间线」；化验单里不再有演示样例按钮。
- 「记录概况」里的「清空本机全部记录」生效，点掉后化验、症状、用药全部消失。
- 化验单、用药记录、症状里的输入框文字完整显示。
- **概览页不再出现任何状态色块或「规则命中」**，只有记录数量、最近报告日期、以及「最近报告未包含的项目」。
- 加入六次模拟记录后，趋势页能画出曲线（纯描点连线，无判断）。
- 编辑已有报告后数量不增加；用药与症状的增改删都生效。
- 摘要页：生成摘要后出现「预览 Word 摘要 / 发送 Word 到聊天 / 复制纯文本」。
- **预览 Word**：文档标题为「家庭记录助手 · 就诊摘要」，化验与用药是表格，文末有「最近一份报告未包含的项目」与边界声明。
- **发送 Word**：能调起微信转发，文件名形如 `家庭记录助手-就诊摘要-2026-10-15.docx`；转发不可用时应有明确提示。
- 单份报告导出：在「历史」打开一份报告，能预览与发送该报告的 Word 表格。
- 上传模拟 PNG 后能预览，并提示不做识别。
- 发现页两栏（就医资源 / 政策资讯）切换、筛选、演示标注、点击只弹演示提示且不发网络请求。
- 记录页子导航出现「评估」；勾选「确诊或疑似 sJIA」与「发热」后，铁蛋白 > 684 且附加条目 ≥ 2 条时 PRINTO 卡显示「符合」。
- 「查询与评估」栏目：选年／月／日后列出该范围内的症状与用药；未记录结束日期的用药，在之后任意一天都应能查到；同栏目下方是按已发表标准的评估结果。
- 概览与摘要栏目已删除：记录概况在「记录」栏顶部，就诊摘要在「记录」栏底部。
- 就医资源卡片新增「相关政策」：点开按医院查看以报销比例为主的演示政策，页面明确标注不是真实医保政策、以参保地医保局口径为准。
- 发现页两个栏目各有一个搜索框：就医资源可按医院名／城市／科室／地址搜，政策资讯可按标题／地区／摘要／标签搜，且与原筛选叠加、可一键清除关键词。
- 只填铁蛋白、无发热无附加条目时 PRINTO 显示「未符合」；完全不填铁蛋白时显示「数据不足」。
- 正常值输入下 MS 评分约 -2.0，卡片里显示已知缺陷提示，且判为「符合」也不能当诊断。
- 评估页顶部与结果区都写明不构成诊断。

## 发布前必须完成（平台要求，非代码）

- 个人主体不能开通医疗健康类目，类目须走「工具」这类；名称、简介、界面文案不得涉及诊断/治疗/用药建议。
- 完成小程序备案（未备案不能发布）。
- 在后台填写用户隐私保护指引：本工程使用相册/摄像头与文件写入转发等隐私相关接口。
- 提交审核通过后才能发布，任何微信用户才可搜索、扫码、分享使用。
- **病友交流（UGC 社区）已删除**；剩余的就医资源仍属医院信息形态。要再降风险，可把发现页换成「关于」页，同样满足 tabBar 至少两项。

## 边界

- 界面采用原生 WXML/WXSS，不是 H5 页面，也不是医疗器械。
- 图片只作附件保存，不做识别；本版本不含 OCR，也不含后端服务。
- 工程包含按已发表标准（2016 PRINTO、2004 HLH、MS 评分表）的**静态评估**，结果只作提示；所有输入仍来自用户手工录入或勾选。
- Word 文档在手机上离线生成，文档内已写明不构成诊断建议。
- 发现页全部为写死的样例数据：不是真实医院，也不是真实政策文件。
- 开发者工具对 `wx.openDocument` 与 `wx.shareFileMessage` 的支持可能与真机不同，导出功能必须以真机验收为准。
- 当前交付为可导入工程，不是已上线、已备案或已完成真机验收的小程序。
